Widget #5 Priority 1 — Do first Long-press app icon → 4-action menu

User long-presses the Zaeli app icon on their Home Screen → iOS pops a quick-action menu with 4 rows. Each row deep-links straight into the relevant app surface, saving the user 2-3 taps vs opening the app cold.

za zaeli
Start with voice 🎤
Today's events 📅
Shopping list 🛒
Quick add ✍
iPhone Home Screen — long-pressed

What it does

4 shortcuts, each routes to a specific surface:

  • Start with voice → open Chat with mic already recording
  • Today's events → open Home with Calendar sheet already expanded
  • Shopping list → open Home with Shopping sheet already open
  • Quick add → open Chat with input focused, ready to type

Technical Low risk

Requires: expo-quick-actions package install + UIApplicationShortcutItems in Info.plist (via app.json) + a small listener in _layout.tsx that reads the tapped shortcut on cold-start AND catches subsequent taps while app is running.

No Swift code. No widget target. No data pipeline. Pure JS + Info.plist.

Build cycles estimate

1-2 EAS builds. If first build shows the shortcuts but routing doesn't work, second build fixes the listener wiring.

iPhone Lock Screen — inline widget highlighted

What it does

One-line text: "☀ 3 events · Soccer 4pm" or "🌙 Bins night" or "🎂 Poppy's birthday". Adapts to time of day + what's on.

Same data shape as the Home tiles headlines — pulled from the family's calendar + reminders for today.

Technical Medium risk

First widget that needs a JS → Swift data pipeline. Uses react-native-shared-group-preferences (already installed Session 35): JS writes JSON to Shared App Group UserDefaults whenever Home data refreshes, Swift widget reads from same UserDefaults on its timeline refresh.

Timeline provider needs to declare a refresh cadence (iOS ultimately decides). Aim for hourly refresh or "on-demand from app" via WidgetCenter.reloadAllTimelines() when data changes.

Build cycles estimate

3-4 EAS builds. First iteration: get widget rendering static text. Second: wire the App Group read. Third: wire JS writes. Fourth: refresh cadence tuning.

What it does

Header: "3 events on today." — same headline as the Home Calendar tile.

List: top 3 events with time + assignee dot (colour-coded per family member).

Footer: next non-event reminder ("Bins out at 8pm") if one falls today.

Tap → deep-link to Home with Calendar sheet expanded (matches tile behaviour).

Technical Medium-high risk

Full data pipeline: JS writes events + reminders shape to App Group whenever Home data refreshes, Swift widget reads on timeline refresh. Layout is more complex than Lock Screen widgets (multiple text lines, colour dots, foot row).

Family colour palette needs to sync to Swift — could hardcode initial palette in the widget, revisit if family customises.

Build cycles estimate

4-5 EAS builds. Biggest chunk of native work. Ideal to tackle only after #4 has proved the data pipeline works.
